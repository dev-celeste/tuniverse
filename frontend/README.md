# Tuniverse frontend

React + TypeScript + Vite. The design reference is [`docs/prototype/tuniverse-galaxy.html`](../docs/prototype/tuniverse-galaxy.html).

## Run it

Needs Node 24 (pinned in `.nvmrc`) and the backend running on `127.0.0.1:8000`.

```bash
nvm use
npm install
npm run dev
```

Open **http://127.0.0.1:5173**. Use `127.0.0.1`, not `localhost`: the session cookie is scoped to the host, and the backend and Spotify redirect URI use `127.0.0.1`.

The backend's `.env` needs `FRONTEND_URL=http://127.0.0.1:5173` so Spotify login returns here.

## How it talks to the backend

- The Vite dev server proxies `/api` to the backend, so every request is same-origin and the HttpOnly session cookie is sent automatically. Production uses the same shape (see [`docs/DEPLOYMENT.md`](../docs/DEPLOYMENT.md)).
- **Connect Spotify** is a full-page navigation to `/api/v1/auth/login`. After login the backend redirects to `/?welcome=1` (the start screen, which then dives into `/galaxy`), or to `/?login_error=<code>` on failure.
- Response types in `src/api/schema.d.ts` are generated from the backend's Pydantic models. After changing `backend/models`, regenerate them:

  ```bash
  npm run gen:api
  ```

## Sessions and protected pages

Pages that need Spotify go inside the `RequireSession` layout route in `src/App.tsx`. It checks the session with `/spotify/me`, then:

| Result | What happens |
|---|---|
| Signed in | The page renders; read the user with `useSessionUser()` |
| 401, never signed in | Start screen |
| 401 after being signed in | Start screen with "Your session ended…" |
| 403 | Start screen with "This Spotify account isn't on the invite list yet…" |
| Other errors | Error card with **Try again** |

A 401 from any other request (an expired or revoked session, or a backend restart with in-memory sessions) re-checks the session, so these rules apply app-wide. Log out with `useLogout()`.

| Script | What it does |
|---|---|
| `npm run dev` | Dev server at 127.0.0.1:5173 with the `/api` proxy |
| `npm run build` | Type-check and build to `dist/` |
| `npm run lint` | Lint with oxlint |
| `npm test` | Run the tests once (Vitest + React Testing Library); `npm run test:watch` to keep them running |
| `npm run gen:api` | Regenerate API types from the backend's OpenAPI schema |

## Routes

| Path | Page |
|---|---|
| `/` | Start screen over the demo galaxy, seen from far out: Connect Spotify / Enter your universe, demo entry, login error messages |
| `/galaxy` | Your 3D galaxy: planets, moons, constellation, mood nebula, panels, time ranges. Protected |
| `/demo` | The same experience on sample data: no login, no Spotify calls |

All three share one persistent 3D scene (`components/Universe.tsx`); pages choose what it shows with `useSceneConfig`, so moving between them flies the camera (the dive) instead of reloading.

The demo data in `src/demo/demo-universe.json` is generated by the backend from sample artists run through the real pipeline: `cd backend && .venv/bin/python -m demo.universe`. A backend test fails if it's out of date.

## In-app player

Song rows in the planet and top-tracks panels play in a **Now playing** dock (`components/NowPlaying.tsx`) using Spotify's embedded player: previews for visitors, full songs for anyone signed in to Spotify in that browser. The dock stays while you explore, and the playing song's star and moon stay lit. Each row also has a small ↗ link to open the song in Spotify. Nothing loads from Spotify until a song is picked. The demo uses real Spotify track ids, so its songs play too.

## Accessibility and small screens

- **Keyboard and screen readers:** the core ("You"), every planet name and the constellation and nebula captions are buttons in a `Galaxy` landmark, after the page header in the tab order. Opening a view moves focus to the panel's heading; Esc or the back button returns it to whatever opened the view. On the start screen the scene is `inert`, so its hidden labels stay out of the tab order.
- **No WebGL:** when the browser can't draw the scene (`galaxy/webgl.ts`), or the scene fails to start (`components/SceneBoundary.tsx`), the 2D starfield stays and the galaxy pages show a list view (`components/GalaxyList.tsx`) that opens the same panels.
- **Phones:** upright, the header takes two rows, the mood card shrinks to its headline and the panel is a bottom sheet. Sideways (short screens), the header fits one row and the panel moves to the side. `sidePanelWidth()` in `galaxy/places.ts` mirrors those media queries so the camera keeps the focused object clear of the panel.
- **Reduced motion:** with `prefers-reduced-motion`, there's no intro flight or warp, orbits slow down and panel transitions are instant.
